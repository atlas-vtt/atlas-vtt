# Scene Tab Reordering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let users drag open scene tabs into their preferred order and retain that order across workspace restoration.

**Architecture:** An ID-based move action changes only the per-view tab array. A synchronous view method requests workspace persistence, and the tab bar calls it for keyboard moves or completed pointer drops. Reuse the existing pointer-session helper; keep geometry and edge scrolling in focused scene-tab code.

**Tech Stack:** Existing React, TypeScript, Zustand, Sass, Vitest and Chromium/Playwright. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-23-scene-tab-reordering-design.md`

## Global Constraints

- Use `feature/reorder-scene-tabs`, created directly from upstream `beta` at `ebbebdbd7e45fe359cf6d8ed8195f3e571d2195b`.
- Include no merchant or token-sound commits in this PR.
- Persist using the existing `AtlasView.getState()`/`setState()` tabs array.
- Read the latest store state when committing. Reuse each existing `SceneTab` object and change only array order.
- Request Obsidian's layout save exactly once when the action changes order.
- Commit order only on a valid drop. No dependencies, settings, vault-data migration, scene format, or network protocol changes.
- Use the tab strip's owner document/window for popouts, never the global document/window.
- Preserve unrelated `.obsidian/` files and the existing merchant branch/test ZIP. No push, merge, or PR creation during implementation.

## Review Focus

- Order-only notifications must leave local and online presentation bound to the same scene, without holding or reloading frames.
- Closing/renaming/opening a tab during a drag must preserve current metadata and never resurrect a closed tab.
- A stationary pointer at an overflow edge must keep scrolling and update the insertion target in scrolled coordinates.
- Keyboard moves and canceled drags must preserve focus and leave the next deliberate click functional.
- A restored workspace and a separate/popout Atlas view must preserve ID-to-scene/camera associations and independent order.
